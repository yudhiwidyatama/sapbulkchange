# FI assignment upload: Phase 2 integration slice

**Not production-ready.** No live FI writes can be made by this delivery. [Design](../FIORI_APP_SPEC.md) · [policy and activation gates](../FIORI_AUTHORIZATION.md).

## Try the page with synthetic data
Use Python 3.12, `python -m pip install openpyxl==3.1.5 defusedxml==0.7.1`, then `python test/demo_server.py` from this directory. Open http://127.0.0.1:8080/ (internet access for the SAPUI5 runtime is needed by this local preview). Do not use real company data. The demo binds only to loopback, is single-user, stores runs in memory and never connects to SAP. For a SAP-hosted deployment use the landscape's SAPUI5 resources and same-origin application service. Target runtime availability is not yet verified in QAS.

1. Download the template. In its first data row enter `42`, `2022`, `1`, `SA`, `20220131`, `4000`, `NEW`, `BEBAN` in column order. Save as `.xlsx`.
2. Select company `DEMO`, choose the file and Validate. Refresh until READY. Row 2 should show `0000000042 / 2022 / 001`, OLD → NEW, PLANNED. Apply remains disabled: the demo has no FI writer. Repeat the input row to exercise full-file duplicates and downloadable errors.
3. Reload in the same tab to resume by run ID; only the ID is retained in session storage. Restarting the demo clears runs. Tests: `node --test test/client.test.cjs`, then, with the demo running, `python test/test_demo.py -v`.

## Files and integration contract
- `webapp/manifest.json`, `Component.js`, `index.html`: Fiori elements custom page shell. `view/Upload.view.xml`, `controller/Upload.controller.js`, `i18n/i18n.properties`: file/company selection, validation, status refresh, 100-row pages, confirmation and export. `model/Template.js`: actual header-only text-formatted Excel workbook; `model/RunClient.js`: CSRF-protected same-origin OData transport. No end-user identity is supplied by the UI. [SAP FPM](https://ui5.sap.com/test-resources/sap/fe/core/fpmExplorer/overview/introduction.html) · [FileUploader API](https://ui5.sap.com/#/api/sap.ui.unified.FileUploader).
- `test/metadata.xml`: contract, not an activated SAP service. `POST Runs` binds authenticated owner and company and returns UUID plus ETag. `PUT Runs(uuid)/Workbook/$value` seals bytes once against ETag and queues validation. `GET Runs(uuid)` reports run status/counts/ETag. `Rows` returns authorized pages; `ErrorCsv/$value` exports all authorized errors. Bound `Apply` must independently check owner, state, policy and current ETag and enqueue at most once. `CompanyCodes` returns only authorized companies. Never treat ApplyAllowed or a run UUID as authorization.
- `backend/adt/zfi_astra_run.ddls`: create as a client-dependent database table in ADT. `backend/zcl_fi_run_store.clas.*`: server-assigned owner and run UUID, immutable staging, compare-and-set claim/completion and background-owner check. The caller owns the LUW; a queue transition and successful job submission must be coordinated and recoverable. Staging is private: no general-purpose table access or direct media reads. Raw staging is not an FI preview. The run store intentionally offers no FI-write transition.
- `test/demo_server.py`, `test/test_demo.py`, `test/client.test.cjs`: synthetic HTTP fixture, size/count and client contract tests. Mock row validation is limited to the documented test posting and canonical headers; it is not the SAP parser or an authorization implementation.

## Not delivered / verification gates
Production OData binding/handlers, authorized company help/results/export, full SAP workbook/ZIP admission and alias parser integration, persisted per-document checkpoints, requester-bound SAP scheduler/worker, SLG1 integration, the signed-off eight-object FI policy and live change/read-back adapter are not wired. No production authorization or transactional guarantees are inferred from fixture tests. No ABAP activation, 50,000-row SAP performance qualification or QAS role-based test has been performed. Keep Apply unavailable until the gates in the design are met.
