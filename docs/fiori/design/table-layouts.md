# Assignment Runs: logical data model and table layouts

Design baseline for [service and persistence](service-data.md), [screens](experience.md) and [FI execution](execution.md). This is not activated DDIC, a transport, a retention approval or a change to the report. Names below are proposed customer tables. The distinction that must survive any physical mapping: **one workbook row is not one FI operation**. Keep the reviewed input immutable; store later execution evidence separately.

## Relationships and notation

```text
RUN ──< FILE ──0..1 BLOB           replacement upload = new file
RUN ──< PLAN >── FILE              each plan snapshots exactly one file of this run
PLAN ──< ROW >──0..1 TARGET        many eligible rows may reference one target
ROW ──< MSG                        ordered preparation diagnostics
PLAN ──0..1 SUB ──0..1 QUEUE       Plan Only has no queue entry
SUB ──< DOC ──< RESULT >── TARGET  one result per distinct submitted item
RUN ──< EVENT                      append-only history, optionally narrower scope
```

All primary keys and all relationships start with `MANDT:CLNT(3)` (implicit below); no cross-client join, lookup, claim or deletion. `R` = run ID RAW(16); `V` = positive plan version INT4; `F`, `T`, `X` = file, target and execution IDs RAW(16); `S` = original worksheet row INT4, not a display sequence. `D` = `(BUKRS CHAR(4), BELNR CHAR(10), GJAHR NUMC(4))` and `I` = `BUZEI NUMC(3)`; use the corresponding SAP elements, not integers. `L` = ledger CHAR(2), `DOCLN` = ledger line NUMC(6), `A` = assignment CHAR(18). `U` = authenticated backend username (SYUNAME); `TS` = UTC long timestamp; `N` = nonnegative INT4; `REV` = monotonically increasing INT8; `H` = SHA-256 RAW(32); `TEXT` = variable Unicode text, `BIN` = exact byte sequence. `CODE` = controlled internal CHAR(32), not translated display text. Use stable codes from the domain named by the field. IDs presented to clients are opaque strings. Preserve FI leading zeroes.

`?` means logically absent; all other fields required. ABAP initial values must not silently mean known zero, blank assignment, or a matched BSEG row. Where DDIC cannot represent absence use an explicit presence/state flag or separate optional child row. DDIC representation of long text/bytes, names and indexes to be validated on the target; no truncation of diagnostic messages or file bytes. All writers below are trusted backend components, never browser identities/values accepted as authoritative.

## Field dictionary

Primary key is in the second column; fields in that key are mandatory fields of the record. Each row defines one stored record type. `R,V` always identify a plan of the same run and client.

| Table / one record per | Primary key after MANDT | Other fields, meaning and references | Writer and mutation rule |
|---|---|---|---|
| `ZFA_RUN` / run | `R` | `owner:U, created:TS, updated:TS, revision:REV, state:CODE, draft_company:BUKRS, draft_ledger:L, draft_mode:CODE, draft_limit:N, draft_file:F?, current_version:V?`. Limit 0 means all. Draft references must belong to R. Revision is the source of the opaque ETag. | Service creates; edits draft inputs only. Repository changes lifecycle/revision conditionally. Revision of Prepared clears the current-plan pointer, not the old plan. Allocate the next V under a run-level concurrency guard; never reuse an old V. |
| `ZFA_FILE` / upload metadata | `R,F` | `filename:TEXT, media_type:TEXT, byte_length:INT8, digest:H, uploaded_by:U, uploaded_at:TS, expires_at:TS?, purged_at:TS?`. Length nonnegative. | Upload service inserts metadata and payload together. Filename, length and digest immutable. Retention process alone records purge. |
| `ZFA_BLOB` / private payload | `R,F` | `content:BIN`; same key as FILE. Recalculate length and digest from received bytes. No public media link. | Insert once. Remove bytes independently of metadata only when policy and evidence guards allow. |
| `ZFA_PLAN` / successful Prepare | `R,V` | `file:F, file_digest:H, company:BUKRS, ledger:L, mode:CODE, doc_limit:N, prepared_by:U, prepared_at:TS, source_rows:N, eligible_items:N, eligible_docs:N`. All refer to this immutable preview, not current draft fields. | Planner/repository inserts header, rows, targets and messages together after checking run revision. Fatal upload/header error creates no partial plan; record a run event. |
| `ZFA_ROW` / retained source row | `R,V,S` | `input_doc:TEXT?, input_year:TEXT?, input_item:TEXT?, input_type:TEXT?, input_date:TEXT?, input_gl:TEXT?, input_source:TEXT?, input_target:TEXT?` (only contract columns as policy permits); `belnr:BELNR?, gjahr:GJAHR?, buzei:I?, source:CODE?, doc_type:CHAR(2)?, posting_date:DATS?, gl:CHAR(10)?, old:A?, target_value:A?, plan_status:CODE, target_id:T?`. Document/company context from PLAN. Invalid values never forced into FI types; a row without an FI key remains identifiable by S. | Prepare inserts once. A PLANNED row links to one TARGET of this plan. Excluded/error rows have no execution link. Store applicable comparison values and warnings even on noneligible rows; use MSG for field-specific detail. Do not copy entire unrelated worksheet columns. |
| `ZFA_MSG` / ordered preparation diagnostic | `R,V,S,seq:N` | `severity:CODE, reason:CODE, field:CHAR(30)?, expected:TEXT?, actual:TEXT?, message:TEXT`. Multiple comparisons per row; blank SAP value can be known. | Planner inserts with ROW; immutable. Fatal file/run errors belong to EVENT instead. |
| `ZFA_TARGET` / unique eligible FI item in a preview | `R,V,T` | `D,I,docln:DOCLN,source:CODE,doc_type:CHAR(2),posting_date:DATS,gl:CHAR(10),old:A,target_value:A,clearing_doc:CHAR(10)?`. Ledger from PLAN. Unique `(MANDT,R,V,D,I)`; company must match PLAN. DOCLN is the matched ledger line, not a different FI change key. | Planner inserts once; worker may not overwrite reviewed values. No target for an ambiguous or excluded item. Whether a mixed-validity duplicate group qualifies is a planner rule, not decided by a database join. |
| `ZFA_SUB` / accepted submission of a plan | `R,V` | `execution:X, token:TEXT, request_digest:H, actor:U, submitted_at:TS, mode:CODE, live_confirmed:CHAR(1), confirmed_at:TS?`. Unique `(MANDT,X)`. Request digest covers the canonical application request (run/version/mode/confirmation/token), not transient transport headers. File digest/scope referenced via PLAN. | Submit inserts once after ownership and scope checks. On identical authorized replay return existing X; altered request cannot create another. Record Plan finalization without dispatch; explicit confirmation only for Live. |
| `ZFA_QUEUE` / durable work intent | `X` | FK to SUB by unique X; `dispatch_state:CODE, revision:REV, created:TS, updated:TS, attempts:N, dispatch_claim:RAW(16)?, claimed_at:TS?, scheduler_ref:TEXT?, last_error:TEXT?`. X is also the dispatch correlation ID. | Same transaction as SUB for Test/Live, never for Plan. Dispatcher conditionally claims/updates. Missing scheduler reference is not proof no job started. |
| `ZFA_DOC` / submitted document checkpoint | `X,D` | `phase:CODE, revision:REV, attempt:N, claim:RAW(16)?, worker:U?, claimed_at:TS?, checkpoint_at:TS, outcome:CODE?, diagnostic:TEXT?`. X determines R,V. | Worker claims once per active document of this execution; fenced updates by revision/claim. Persist intent before FI and outcome afterward; never commit metadata within the FI transaction. Do not confuse this logical claim with the SAP FI document lock across runs. |
| `ZFA_RESULT` / execution observation per target | `X,T` | `D,I, outcome:CODE?, read_state:CODE, observed:A?, observed_at:TS?, diagnostic:TEXT?`. Parent DOC `(X,D)`; T must belong to the exact plan selected by X, and its FI key must match D,I. `read_state`: NOT_READ, READ_UNAVAILABLE, ITEM_MISSING, VALUE_READ. `VALUE_READ` requires observed (may be blank) and timestamp. ITEM_MISSING is a completed read, not a blank value. | Worker/verification reader only; conditional writes tied to DOC claim. Re-reading is not a new FI attempt. Document-wide failure can be stored on DOC and projected to linked rows. No authoritative new status written back into ROW. |
| `ZFA_EVENT` / audit or diagnostic event | `R,event_no:INT8` | `at:TS, actor:U, kind:CODE, from_state:CODE?, to_state:CODE?, version:V?, execution:X?, company:BUKRS?, belnr:BELNR?, gjahr:GJAHR?, correlation:RAW(16), reason:CODE?, detail:TEXT?`. On reconciliation record the authorized decision, evidence reference and scope; do not attach raw traces. | Backend component responsible for transition appends; same business transaction as the state it documents where possible. No edit-in-place or silent retry. Never log workbook contents. |

## Integrity, access paths and lifecycle

- Prepare counts: `source_rows` counts retained ROW records (including invalid rows); `eligible_items` counts TARGET records; `eligible_docs` counts distinct D in TARGET. Review warnings are diagnostics, not extra eligible rows. Compute result counts from one consistent projection; never count repeated worksheet links as repeated FI work.
- Persist plan publication and RUN pointer/revision atomically. An older version retains its own FILE and inputs after a new upload. SUB references that exact version. Only a current reviewed version may be newly submitted. FKs always include MANDT; additionally enforce same-run/same-plan relationships in the repository where DDIC foreign keys cannot enforce them at write time.
- Access paths (candidate indexes, all prefixed by MANDT): RUN `(owner,draft_company,created,R)` and `(state,updated,R)`; ROW primary key for worksheet order and `(R,V,target_id,S)` for outcome fan-out; unique TARGET FI key and SUB execution ID as above; QUEUE `(dispatch_state,updated,X)`; DOC `(phase,checkpoint_at,X)`; FILE `(expires_at,R,F)`. Check actual access plans before adding further indexes.
- Every list, count, child, stream or CSV lookup starts from the authorized RUN and relevant company; a child ID alone grants nothing. No public BLOB projection. Only approved client policies set retention/limits. Do not purge active runs, unverified commits, unresolved cases or referenced evidence. Remove dependent records in a controlled retention transaction; never cascade from a replaced draft file into an older plan. No production retention durations or role assignments set by this design.

## Read layouts (not additional tables)

| Screen / row grain | Desktop columns in initial order → source | Sort/filter and narrow layout |
|---|---|---|
| Assignment Runs / one RUN | Run ID → RUN.R; File → FILE.filename; Company, Ledger → current PLAN or draft; Created by / Created at → RUN.owner/created; Mode, Run state → PLAN or draft mode / RUN.state; Results → scoped status counts. | Latest created first, R tie-breaker. Filter company, mode, state, created date; default own runs. On narrow screens retain run/file and textual state; other fields accessible in details. |
| Review / one ROW | Worksheet row → S; Document / Year / Item → ROW normalized key; Source → ROW.source; Old / Target → ROW.old/target_value; Plan status → ROW.plan_status; Reason → MSG ordered by seq. Eligible items/documents in header → PLAN counts. | Default S ascending; keep S visible in detail under any sort. Keep document/item, target and text status on narrow screens. Invalid row remains visible even without a key. No editing SAP facts. |
| Run details / one ROW | Same row/key, source and old/target; Verified assignment → RESULT.read_state/observed; Status and Message → resolved execution outcome and diagnostics, else plan status and MSG. | Server paging, status filter; S as stable tie-breaker. Preserve excluded row status; do not show CHANGED for a pending read. Render known blank as “Blank”, no completed read as “Not verified”, and missing item as “Item not found”. Narrow layout as Review; secondary values in accessible details. |

The FI outcome fans out only through a valid ROW → TARGET → RESULT link. Document denial applies to every linked planned sibling, not to rows already excluded. Full-run CSV uses worksheet order and the existing eight columns `doc,year,item,source,old,target,status,message`; no audit columns, no current-page restriction. Snapshot availability by run state remains a separate export decision.

## Design walkthroughs (expected, not target test results)

1. Rows 2 and 5, identical validated FI key/target: two ROW keys, one TARGET, two links to T. Live submission has one SUB, one QUEUE, one DOC and one RESULT for that item. Both visible rows receive that result; neither is lost from export.
2. Row 7 with no valid BUZEI: ROW `(R,V,7)` and an error MSG, no target ID or RESULT. A left join keeps row 7 visible. No fabricated `000` FI key.
3. Edit Prepared V1 and replace file F1 with F2: RUN becomes Draft; Prepare inserts V2. V1 still names F1. A new Submit for V1 is rejected. Losing the response to an already accepted identical Submit for V2 returns its original X, never a second queue record.
4. Commit known, read unavailable: DOC checkpoint survives; RESULT has READ_UNAVAILABLE and no observed assignment. Retry only the read. A later successful read returning a blank is VALUE_READ with known blank, distinct from ITEM_MISSING. An unknown commit goes to reconciliation regardless of equality on a later read.
